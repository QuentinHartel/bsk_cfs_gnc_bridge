# Project State — Basilisk ↔ cFS GNC Bridge

## What this is
A software-in-the-loop bridge between Basilisk (astrodynamics sim) and
NASA cFS (flight software framework), built as a portfolio project for
GNC/flight-software internship applications. Basilisk simulates truth
dynamics/sensors/actuators; a custom cFS app (`gnc_app`) implements
attitude determination and control, connected via a planned ZeroMQ
bridge.

## Environment
- WSL2 (Ubuntu) on Windows
- Repo: `~/bsk_cfs_gnc_bridge` (git, pushed to GitHub)
- cFS: submodule at `cfs/`, build config `native_std`
- Basilisk: v2.10.2, built from source at `~/dev/basilisk` (own venv)

## Next step (not yet started)
Design and build the ZeroMQ bridge connecting the two frameworks:
1. Define message schema (sensor data: gyro/attitude; actuator cmds:
   torques) — shared between Basilisk-side Python and cFS-side C
2. Basilisk-side: a Python module/monitor publishing sensor sim output
   over ZeroMQ each timestep
3. cFS-side: extend `gnc_app` to subscribe, run attitude determination
   (TRIAD or EKF) + a control law (detumble/pointing), publish actuator
   commands back
4. Validate closed-loop behavior against a Basilisk-native FSW baseline

## Key gotchas already solved (see docs/gotchas.md for full detail)
- cFS startup script (`cfe_es_startup.scr`) is auto-generated by
  `sample_defs/generate_startup.cmake`, not hand-edited — has a
  **hardcoded app allowlist** (`CFS_APP_STARTUP_ORDER`) separate from
  `targets.cmake`'s `_APPLIST`; app entry point names must match the
  generator's fixed `${APP_UPPER}_AppMain` convention
- `CFE_ES_RegisterApp()` is deprecated/removed in current cFE — don't
  call it
- `CFE_ES_WriteToSysLog` doesn't print to console — use
  `CFE_EVS_SendEvent` for visible status messages
- Use `make native_std.prep`/`.install`, not bare `make prep`
  (avoids RTEMS toolchain requirement)
